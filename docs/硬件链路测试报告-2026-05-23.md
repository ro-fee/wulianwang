# 硬件链路测试报告

**日期**: 2026-05-23  
**分支**: `hardware-leg-sensors`  
**测试目标**: 验证 ESP-NOW → Hub → BLE → PC 全链路数据通畅

---

## 1. 测试架构

```
[肘部 ESP32-S3] ──ESP-NOW──┐
                            ├── [腰间 Hub ESP32-S3] ──BLE──▶ PC (前端)
[腿部 ESP32-S3] ──ESP-NOW──┘
```

- **肘部卫星**: 模拟手臂 6 角度 + 足底 18 压力，33Hz 发送
- **腿部卫星**: 模拟腿部 6 角度，33Hz 发送
- **腰间 Hub**: ESP-NOW 双路接收 → BLE Notify 转发给 PC

## 2. 硬件配置

| 设备 | COM 口 | MAC 地址 | 固件 |
|------|--------|----------|------|
| 腰间 Hub | COM7 | `28:84:85:6D:68:0C` | `hub-waist.ino` |
| 肘部卫星 | COM6 | `28:84:85:6D:67:FC` | `test-elbow.ino` |
| 腿部卫星 | COM8 | `28:84:85:6D:67:F8` | `test-leg.ino` |

全部为 ESP32-S3 (QFN56, rev v0.2)，4MB Flash + 2MB PSRAM。

## 3. 测试过程

### 3.1 准备阶段

1. 用 `esptool read-mac` 读取腰间 Hub MAC 地址（因为串口监视器无法获取）
2. 将 Hub MAC 写入 `test-elbow.ino` 和 `test-leg.ino` 的 `WAIST_MAC[]`
3. 安装 `arduino-cli` 用于命令行编译烧录

### 3.2 遇到的问题及解决

#### 问题 1: 测试固件与正式固件文件夹冲突

- **现象**: `test-elbow.ino` 与 `rgc-backend.ino` 在同一目录，Arduino 编译时报 `redefinition of 'void setup()'`
- **解决**: 将测试固件移至独立文件夹（`test-elbow/test-elbow.ino`、`satellite-leg/test-leg/test-leg.ino`）

#### 问题 2: TWO_PI 宏冲突

- **现象**: 编译报错 `expected unqualified-id before numeric constant`
- **原因**: ESP32 Arduino 核心在 `Arduino.h` 中已定义 `#define TWO_PI 6.283185307179586476925286766559`
- **解决**: 删除测试固件中重复的 `static const float TWO_PI` 声明

#### 问题 3: USB CDC 串口无输出（核心问题）

- **现象**: Hub 应用层串口输出正常，但两颗卫星完全无输出
- **原因**: 
  - ESP32-S3 使用 USB-Serial/JTAG（PID:VID=303A:1001），`Serial` 默认映射到物理 UART0 引脚（GPIO43/44），而非 USB
  - 需要启用 `CDCOnBoot=cdc` 才能将 `Serial` 映射到 USB CDC
  - 但启用后 RTS 复位会误触下载模式，导致芯片卡在 bootloader
- **解决**: Hub 使用 `CDCOnBoot=cdc`（需串口观察），卫星使用默认配置（不需串口，ESP-NOW 静默工作）。卫星烧录后需**拔插 USB 冷启动**才能正常运行

#### 问题 4: 烧录后芯片不运行应用

- **现象**: esptool 烧录校验成功，但板子不运行应用程序，串口显示 `waiting for download`
- **原因**: ESP32-S3 的 USB-Serial/JTAG 在 RTS/DTR 特定时序下会进入下载模式而非正常启动
- **解决**: 物理拔插 USB 线冷启动（`esptool --after hard_reset` 无法可靠退出下载模式）

## 4. 测试结果

Hub 串口输出：
```
[STAT] 肘部数据: 有 (0.0s前) | 腿部数据: 有 (0.0s前)
```

**两条 ESP-NOW 链路均正常工作**，33Hz 数据实时送达 Hub。

## 5. 结论

### 硬件层面：可行

- ESP32-S3 × 3 的 ESP-NOW 星形拓扑工作正常
- 双路 33Hz 实时数据传输无丢包
- BLE + ESP-NOW + WiFi 三栈共存稳定（同芯片运行）

### 软件层面：可行

- V2 数据包格式（68 字节：12 角度 + 18 压力）经 ESP-NOW → BLE 完整透传
- Hub 端临界区保护的接收/转发逻辑正确
- 模拟数据生成器（正弦步态、半波整流压力）能驱动前端渲染

### 已知注意事项

1. ESP32-S3 USB-Serial/JTAG 烧录后建议**拔插冷启动**，避免芯片卡在下载模式
2. 若需串口调试输出，加 `CDCOnBoot=cdc` 编译选项，但注意拔插后才能正常输出
3. 传感器到货后，将测试固件替换为正式版 `satellite-leg.ino` 和 `rgc-backend.ino` 即可

## 6. 附录：常用命令

```bash
# 读取 ESP32 MAC
python -m esptool --port COM7 read-mac

# 编译（带 CDC 串口）
arduino-cli compile --fqbn "esp32:esp32:esp32s3" --board-options "CDCOnBoot=cdc" sketch.ino

# 烧录（带 CDC）
arduino-cli upload --fqbn "esp32:esp32:esp32s3" --board-options "CDCOnBoot=cdc" -p COM7 sketch.ino

# 烧录（无 CDC，卫星默认）
arduino-cli upload --fqbn "esp32:esp32:esp32s3" -p COM6 sketch.ino
```
