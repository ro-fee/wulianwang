# 3D 模型骨骼动画调试记录

**日期**: 2026-05-23  
**模型**: `manModule.fbx` (Mixamo 骨骼, FBX 格式)  
**引擎**: Three.js FBXLoader

---

## 1. 调试目标

让 3D 骨骼模型根据传感器角度数据（Roll/Pitch/Yaw）实现自然的人类走路动画。

---

## 2. 问题与解决方案

### 问题 1: 腿在头上走

**现象**: 腿部骨骼飞到头部上方，而不是在身体下方。

**原因**: `updateJoints()` 用 `child.rotation.copy(euler)` 直接覆盖了骨骼的原始 rest pose。大腿骨 rest pose 的 Z=180° 旋转被清零，导致大腿默认朝向（向上）未修正为向下。

**解决**: 大腿骨的 rest pose 需要保留 Z=180°。在 Euler 角度中显式加上 `LEG_REST_Z = 180°`：
```javascript
child.rotation.set(-Pitch, Yaw, Roll + LEG_REST_Z);
```

---

### 问题 2: FBX 骨骼重复节点覆盖 rest pose

**现象**: 保存 rest pose 时，每个骨骼被遍历两次（FBX 有同名的 dummy 子节点），第二次的 identity 四元数覆盖了正确的 rest pose。

**解决**: 只保存每个骨骼名的第一个四元数：
```javascript
if (!boneRestQuats[child.name]) {
    boneRestQuats[child.name] = child.quaternion.clone();
}
```

---

### 问题 3: 旋转顺序错误 — ZXY vs XYZ

**现象**: 所有旋转方向都不对，调了一下午。

**原因**: 代码假设骨骼使用 `ZXY` 旋转顺序，但 FBXLoader 加载的 Mixamo 骨骼实际使用 `XYZ` 顺序。

**调试方法**: 在模型加载后打印 `child.rotation.order`，发现全部为 `XYZ`。

**解决**: 将所有 `child.rotation.order` 和 `Euler(..., 'ZXY')` 改为 `'XYZ'`。

---

### 问题 4: 手臂 T-pose → A-pose 转换

**现象**: 模型初始姿态为 T-pose（手臂水平侧举），需要改为 A-pose（手臂自然下垂）。

**解决过程**:
1. 尝试在 Z 轴加 70° → 手臂向前平举
2. 尝试在 X 轴加 70° → 一手上一手下
3. 最终确定：**X 轴 +80°**，左右臂相同值，不加镜像符号

```javascript
const ARM_DOWN_ANG = THREE.MathUtils.degToRad(80);
// X = ARM_DOWN_ANG, Y = Yaw, Z = Roll + Pitch
```

---

### 问题 5: 骨骼轴与传感器轴的对应关系

**关键发现**: 在 XYZ 旋转顺序下：

| 骨骼 | X 旋转 | Y 旋转 | Z 旋转 |
|------|--------|--------|--------|
| **视觉方向** | 前后摆 (Pitch) | 扭转 (Yaw) | 左右摆 (Roll) |

统一映射公式：
```
X = -Pitch + offset
Y = Yaw  
Z = Roll + offset
```

---

### 问题 6: 同侧手脚同步（"双拐"步态）

**现象**: 走路时左手和左脚同时向前，像拄双拐，而非自然的交叉步态。

**原因**: 数据生成器中手臂和同侧腿使用相同相位。自然走路应为交叉步态（左手前摆 ↔ 右脚前迈）。

**解决**: 数据生成器中同侧腿相对手臂偏移 π 相位：
```python
arm_phase = t * freq * 2π + offset
leg_phase = arm_phase + π   # 同侧手脚反向
```

---

### 问题 7: 左右臂同时摆动（不交替）

**现象**: 两只手臂同时前摆、同时后摆，不交替。

**原因**: 左右臂的 X 轴是镜像的（自然解剖结构）。传感器给左右相反值（左 +25°、右 -25°），经过同样的符号处理得到不同 Euler 值，在镜像骨骼上产生相同物理方向。

**核心规则**: **镜像骨骼上，相同 Euler 值 → 相反物理方向。**

**解决**: 右手 Pitch 取反（`-cr.y`），使左右臂 Z 值相同：
```javascript
Z = signRoll * Roll + (isRight ? -Pitch : +Pitch)
```

---

### 问题 8: 手臂前后摆动方向

**现象**: 手臂前后摆动的方向反了。

**解决**: 经过多次尝试（X/Y/Z 轮换），确定 Pitch 放在 **Z 轴** 对手臂产生正确的前后摆动（配合 XYZ 旋转顺序和 A-pose 偏移）。

---

## 3. 最终骨骼配置

```javascript
// 上臂
child.rotation.set(80°, signYaw*Yaw, signRoll*Roll + (isRight ? -Pitch : +Pitch))

// 下臂  
child.rotation.set(0, signYaw*Yaw, signRoll*Roll + (isRight ? -Pitch : +Pitch))

// 大腿
child.rotation.set(-Pitch, signYaw*Yaw, signRoll*Roll + 180°)

// 小腿
child.rotation.set(-Pitch, signYaw*Yaw, signRoll*Roll)
```

其中 `signRoll = isRight ? 1 : -1`, `signYaw = isRight ? 1 : -1`

---

## 4. 经验总结

1. **先确认旋转顺序** — FBXLoader 的骨骼可能使用任意 Euler 顺序，必须通过 `child.rotation.order` 确认，不能假设
2. **镜像骨骼需要特殊处理** — 左右骨骼 X 轴反向，Euler 值的物理意义在镜像骨骼上不同
3. **保存 rest pose 要排除重复节点** — FBX 有同名 dummy 子节点
4. **加视觉调试辅助** — 在骨骼上挂 RGB 箭头（X=红, Y=绿, Z=蓝）极大加速了调试
5. **单关节测试法** — 用一个关节的非零值（如只抬右腿）来验证轴映射，比直接跑完整动画高效得多
